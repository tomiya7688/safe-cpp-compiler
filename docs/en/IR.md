# Safe LLVM IR / Validator Specification

> English translation. The Japanese version is authoritative.

## 1. MVP1 output

MVP1 officially outputs **Validated LLVM IR**.

```text
AST
 -> Safety Analyzer/Rewriter
 -> LLVM IR
 -> LLVM Verifier
 -> Safe LLVM Validator
 -> Validated LLVM IR
```

Any later LLVM backend consumes this validated IR.

## 2. LLVM Verifier

Run LLVM's own module/function verification first. Structural, typing, or SSA-invalid IR is a compiler error.

## 3. Safe LLVM Validator

Additional checks are required because LLVM-valid IR can still violate Safe C++ Compiler policy.

MVP1 should avoid dangerous optimization hints and flags by default.

Required checks:

- no unsafe use of undef
- no poison used/generated as safe program semantics
- no unproven nsw/nuw
- no unproven inbounds GEP
- no fast-math flags
- no UB-based unreachable
- no unproven llvm.assume
- no unproven nonnull/dereferenceable/noalias/alignment claims
- safety helper ABI is correct
- required trap/check patterns are preserved
- no raw LLVM construct outside the compiler-defined safe subset

## 4. Checked operations

Signed overflow, division, shifts, null checks, and bounds checks use canonical lowering patterns or runtime helpers that the validator can recognize.

MVP1 may prefer helper calls over aggressive IR for easier independent validation.

## 5. Validator limits

This validator is not a general safety prover for arbitrary third-party LLVM IR.

It independently checks that the LLVM subset generated by Safe C++ Compiler follows its lowering contract.

## 6. Failure

A failure is reported as a compiler safety failure, with the LLVM instruction and source location in debug mode.

## 7. MVP2

MVP2 optimizer output also passes this validator or an equivalent lower-level validator.
